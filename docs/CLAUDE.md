## 1. 專案目的

把「財務金融資訊分析」期末報告〈人性溢價與反 AI 烏托邦：AI 狂潮下的逆勢投資組合建構與績效比較〉改寫成網頁，放在 GitHub Pages 上公開。

- 讀者：同學、老師、面試官。假設讀者懂一點投資，但不熟統計。
- 目標：讓讀者在 3 分鐘內看懂研究問題、方法和結論，有興趣再往下看細節。
- 網站是研究成果展示，**不是投資建議**。

## 2. 網站結構與檔案位置

網站放在 R 專案 repo 的 `docs/` 資料夾，GitHub Pages 設定為 main 分支的 `/docs`。repo 其他資料夾是 R 程式，修改網站時不要動到。以下路徑都以 `docs/` 為起點。

```
docs/
├── index.html              首頁：研究問題、關鍵數字、一句話結論、章節卡片
├── CLAUDE.md               本文件（專案規則）
├── AGENTS.md               給其他 AI 工具的入口，內容是「請讀 CLAUDE.md」
├── README.md               GitHub 專案簡介
├── chapters/               章節頁，一章一個 HTML
│   ├── 01-motivation.html
│   ├── 02-assets.html
│   ├── 03-method.html
│   ├── 04-results.html
│   └── 05-conclusion.html
├── notes/                  每一章的原始內容筆記（Markdown），是寫頁面的依據
├── templates/
│   └── chapter-template.html   新章節頁的範本
└── assets/
    ├── css/style.css       全站唯一的樣式表
    ├── js/site.js          導覽列、頁尾、表格排序、互動圖表
    ├── js/report-data.js   報告表 1 至表 6 的數字（唯一數字來源）
    └── img/                圖片，fig-01.jpg 對應報告圖 1
```

規則：

- `index.html` 一定放在 `docs/` 的最上層（GitHub Pages 才找得到首頁）。
- 章節頁只放在 `chapters/`，圖片只放在 `assets/img/`，不要在別處新增資料夾。
- 樣式只寫在 `assets/css/style.css`，不要在 HTML 裡寫 `<style>` 或 `style="..."` 的顏色。
  （例外：熱圖圖例的漸層、長條圖的寬度由程式計算，可以用行內 style。）

## 3. 檔案命名規則

- 一律用**小寫英文、數字、連字號（-）**，不可以有中文、空格、大寫或底線。
- 章節頁：`兩位數編號-英文主題.html`，例如 `06-robustness.html`。編號決定順序。
- 筆記：與章節頁同名，副檔名改成 `.md`，例如 `notes/06-robustness.md`。
- 圖片：`fig-兩位數編號.jpg` 或 `.png`，編號與報告圖號相同，例如報告「圖 6」就是 `fig-06.jpg`。
  不是報告裡的圖，用 `chapter編號-說明.png`，例如 `ch06-weight-change.png`。
- 連結一律用相對路徑：章節頁連回首頁寫 `../index.html`，圖片寫 `../assets/img/fig-01.jpg`。

## 4. 頁面結構

每一個章節頁都要依序包含以下區塊（直接複製 `templates/chapter-template.html`）：

1. `<head>`：`lang="zh-Hant"`、viewport、標題格式「編號 章名｜人性溢價與反 AI 烏托邦」、載入字體與 `../assets/css/style.css`。
2. `<body data-root="../">`：`data-root` 讓 `site.js` 知道回到首頁的相對路徑。首頁是 `data-root=""`。
3. 頁首導覽列：**不要手寫**，由 `site.js` 依 `CHAPTERS` 清單自動產生。
4. 章節標頭：`eyebrow`（CHAPTER 編號｜對應報告第幾章）、`h1` 章名、一行灰字摘要。
5. 「本章重點」提示框（`.callout`）：3 點以內，每點一句話，有數字就寫數字。
6. 內文：每一節用 `h2`，標題沿用報告的節號（例如「4.2 核心績效評估」）。
7. 上一頁／下一頁與頁尾：**不要手寫**，由 `site.js` 自動產生。
8. 最後載入 `../assets/js/report-data.js` 和 `../assets/js/site.js`。

## 5. 內容格式

- 語言：繁體中文，台灣用語。專有名詞第一次出現時寫「中文（英文）」，例如「最大回撤（MDD）」。
- 句子短、口語、一段不超過 5 行。報告原文太長時改寫成白話，但**意思和數字不能改**。
- 數字：
  - 百分比寫成 `8.1%`；表格裡保留報告原始小數（例如 `0.148`），並在表格說明寫出換算方式。
  - 小數位數與報告相同，不要自己四捨五入成不同的位數。
- 圖片：一律放在 `<figure>` 裡，`<figcaption>` 寫「**圖 N：**報告原本的圖名」，`alt` 用一句話描述圖的內容。
- 表格：放在 `<div class="table-wrap">` 裡，表格下方用 `.table-note` 寫「**表 N：**表名」與讀法。
- 提示框用法：
  - `.callout`（藍）：本章重點、背景說明
  - `.callout good`（綠）：結論、正面發現
  - `.callout warn`（紅）：風險、限制、小結中的警告
- 標籤：`.tag short` 表示可放空，`.tag noshort` 表示禁止放空。

## 6. 視覺風格

- 風格：顧問報告風（深藍、白底、細框線），簡潔、專業，不用 emoji、不用可愛插圖。
- 顏色只用 `style.css` 的變數：
  - 主色 `--navy #1F3A5F`、次要 `--navy-light #3D5F8C`、提示框底 `--soft-blue #EEF2F8`
  - 正面 `--green #4F7F63`／`--green-bg #E8F3EC`，警示 `--red #A33A3A`／`--red-bg #F7EAEA`
- 字體：中文 Noto Sans TC，數字 Inter（加 class `num` 讓數字等寬對齊）。
- 必須在手機寬度（約 375px）正常顯示：寬表格放在 `.table-wrap` 裡左右捲動，不能讓整頁橫向捲動。

## 7. 如何新增一個章節頁

以新增「06 穩健性檢定」為例：

1. **寫筆記**：在 `notes/` 新增 `06-robustness.md`，格式照 `notes/README.md`（重點、各節內容、用到的數字與出處、圖表清單）。
2. **放圖片**：圖片放到 `assets/img/`，依第 3 節命名。
3. **建頁面**：複製 `templates/chapter-template.html` 成 `chapters/06-robustness.html`，把所有 `{{ }}` 換成筆記內容。
4. **登記章節**：打開 `assets/js/site.js`，在最上面的 `CHAPTERS` 清單**最後**加一行：
   ```js
   { file: "chapters/06-robustness.html", no: "06", title: "穩健性檢定", summary: "一句話說明這章在講什麼。" }
   ```
   導覽列、首頁卡片、上一頁／下一頁都會自動更新，**不需要改其他頁面**。
5. **首頁備用連結**：在 `index.html` 的 `#chapter-cards` 裡補一行備用連結（給沒開 JavaScript 的瀏覽器）。
6. **新數字**：如果新章節有表格數字，加進 `assets/js/report-data.js`，並在檔案開頭的註解寫出處。
7. 跑一次第 9 節的檢查清單。

新增其他報告（例如另一門課的報告）時，不要混進同一個網站，另開一個 repo，複製這套結構與 CLAUDE.md 再改第 1 節。

## 8. 給 AI 的規則

1. **數字只能來自報告或 `notes/`**。不可以自己推算、補數字或「合理估計」。找不到出處就不要寫，並告訴使用者缺什麼。
2. 每個數字都要能對回報告的表號、圖號或節號。改寫文字時，數字與結論方向不能改變。
3. 發現報告前後數字不一致時，**以表格為準**，在頁面加註「依報告表 N」，並在回覆中告訴使用者哪裡不一致。
4. 不可以加入投資建議或「保證獲利」之類的字眼；結論頁要保留「非投資建議」。
5. 不可以放學號、身分證字號、電話、email 等個人資料；作者名稱統一寫 Terry Lai。
6. 不可以放 API 金鑰、密碼或任何帳號資訊。
7. 不要改動 `CHAPTERS` 以外的導覽邏輯；新增頁面只改第 7 節列出的檔案。
8. 不要引入新的外部函式庫或框架（React、Bootstrap 等）；維持純 HTML、CSS、JavaScript，確保 GitHub Pages 直接能跑。
9. 改完要說明改了哪些檔案、各改了什麼。
